================================================================
 关卡程序脚本说明（Color1 · 2.5D 俯视角 · Godot 4.7）
 用途：说明每个脚本的功能与使用方法，方便后续理解与修改。
 日期：2026-10-03
================================================================

【一、整体架构总览】

  game.tscn（主场景，常驻）
	├─ GameContainer（game_container.gd）── 启动时初始化 SceneManager 并进入起始房间
	├─ RoomContainer（空的 Node2D）─────── 当前房间被实例化到这里，切房时替换
	├─ Player（玩家，常驻，不属于任何房间）
	└─ HUD（CanvasLayer + game_hud.gd）

  Autoload（全局单例，见 project.godot）：
	- GameState     —— 全局常驻状态（房间元数据 / 钥匙 / 开关 / 能力）
	- SceneManager  —— 负责房间切换（卸载旧房 → 加载新房 → 定位玩家）

  核心思路：
	1) 玩家和 HUD 常驻在 game.tscn，不放进房间。
	2) 每次切房，SceneManager 把旧房间 queue_free，把新房间
	   instantiate 到 RoomContainer，并把玩家移动到目标入口。
	3) 房间内需要「跨切房记住状态」的东西（钥匙、拉杆、门、墙、箱子）
	   都继承 StatefulObject，Room 在进/出房间时统一 save/restore。

----------------------------------------------------------------

【二、脚本逐个说明】

--------------------------------------------------------------
1. scripts/game_state.gd  （Autoload 单例：GameState）
--------------------------------------------------------------
  功能：
	全局常驻状态中心。保存：
	  - rooms：      每个房间的 RoomMeta（进入/通关/收集/机关状态）
	  - inventory：  当前持有的钥匙（key_id -> true）
	  - used_keys：  被消耗过的钥匙（用于钥匙重刷，防软锁）
	  - switches：   开关状态（switch_id -> bool）
	  - abilities：  能力（ability_id -> bool）
	  - current_room_id / current_room：当前房间
	并提供全局信号：item_collected / key_added / key_used /
	gate_opened / hint / room_state_changed。

  主要方法（关卡程序常用）：
	  add_key(key_id)        拾取钥匙
	  has_key(key_id)        是否持有该钥匙
	  consume_key(key_id)    消耗一把钥匙（返回是否成功）
	  was_key_used(key_id)   该钥匙是否被消耗过
	  set_switch(id, bool) / is_switch_on(id)   开关读写
	  set_ability(id) / has_ability(id)         能力读写
	  mark_room_visited/cleared(room_id)
	  add_item(room_id, item_id) / has_item(...) 收集物
	  debug_reachability()   运行软锁检查（见 reachability.gd）

  使用方法：
	任何脚本里直接用全局名 GameState.xxx 调用，无需 preload。
	例：GameState.add_key("key_b")

--------------------------------------------------------------
2. scripts/scene_manager.gd  （Autoload 单例：SceneManager）
--------------------------------------------------------------
  功能：
	负责房间切换。核心方法 change_room(target_scene, target_entrance)：
	  1) 退出旧房（emit room_exited → 调 exit() → queue_free）
	  2) load + instantiate 新房间，加入 RoomContainer
	  3) 调新房的 enter()（标记访问、恢复状态、相机边界）
	  4) 把玩家移动到目标入口，速度清零
	内置 0.4s 冷却，防止连续触发切房。

  方法：
	  setup(player, room_container)  注入玩家与容器（GameContainer 启动时调用）
	  change_room(scene, entrance)   切换房间
	  is_busy()                      是否正在切房

  使用方法：
	由 Door 在玩家进入时自动调用，一般不用手写。
	若要在脚本里手动切房：
	  SceneManager.change_room("res://rooms/room_b.tscn", "from_a")

--------------------------------------------------------------
3. scripts/game_container.gd  （game.tscn 根节点）
--------------------------------------------------------------
  功能：
	常驻根节点。_ready() 时调用 SceneManager.setup() 并进入起始房间。
  属性：
	  start_room      起始房间场景路径（默认 room_a.tscn）
	  start_entrance  起始入口 id（默认 "spawn"）
  使用方法：
	改起始关卡：在 game.tscn 选中根节点，改 start_room / start_entrance。

--------------------------------------------------------------
4. scripts/room.gd  （class_name Room，房间基类）
--------------------------------------------------------------
  功能：
	单个房间节点。负责：
	  - enter()：标记访问、应用相机边界、恢复机关状态
	  - exit()：保存机关状态
	  - get_entrance_position(id)：找到匹配的入口位置
	  - save/restore_state()：遍历本房间所有 StatefulObject 保存/恢复
  属性：
	  room_id        房间唯一 id（默认取节点名）
	  camera_limits  相机边界 Rect2（位置, 大小）
	  y_sort_on      是否开 Y 排序（默认 true）
  使用方法：
	每个房间场景的根节点挂此脚本，设好 room_id 和 camera_limits。
	例：Rect2(-400, -300, 800, 600) 表示 x∈[-400,400], y∈[-300,300]。

--------------------------------------------------------------
5. scripts/entrance.gd  （class_name Entrance，入口标记）
--------------------------------------------------------------
  功能：
	房间入口标记（Marker2D）。Door 切房后玩家会定位到 matching 的入口。
  属性：
	  entrance_id  入口 id（默认取节点名）
  使用方法：
	在房间里放 Marker2D 节点，挂此脚本并设 entrance_id。
	Door 的 target_entrance 要与此一致。

--------------------------------------------------------------
6. scripts/door.gd  （class_name Door，门 / 切房触发）
--------------------------------------------------------------
  功能：
	玩家走进门（Area2D body_entered）触发切房。可加锁。
  属性：
	  door_id          门 id（默认取节点名）
	  target_scene     目标房间场景路径（res://...）
	  target_entrance  目标房间的入口 id
	  required_key_id  需要的钥匙 id（空 = 不锁）
	  consume_key      是否消耗钥匙（false = 钥匙可复用）
  视觉：锁住 = 红色，解锁 = 绿色（自动刷新）。
  使用方法：
	放一个 Area2D 节点（配 CollisionShape2D + 一个叫 Visual 的 Polygon2D），
	挂此脚本，填 target_scene / target_entrance。
	需要锁就把 required_key_id 填成钥匙 id。

--------------------------------------------------------------
7. scripts/stateful_object.gd  （class_name StatefulObject，可持久化基类）
--------------------------------------------------------------
  功能：
	所有需要「切房后记住状态」的物体的基类。
	子类实现 save_state() -> Dictionary 和 restore_state(data)。
	Room 会在进/出场时自动统一调用。
  属性：
	  state_id  唯一状态 id（默认取节点名）
  使用方法：
	写新机关时继承它：class_name Xxx extends StatefulObject，
	实现 save_state()/restore_state()，并在 _ready() 里 super._ready()。

--------------------------------------------------------------
8. scripts/key.gd  （class_name Key，钥匙）
--------------------------------------------------------------
  功能：
	玩家碰到即拾取到 GameState 背包，视觉隐藏。
	若被消耗（门消耗），重进房间会重新出现（防软锁）。
  属性：
	  key_id  钥匙 id（默认取节点名）
  使用方法：
	放 Node2D 挂此脚本，子节点：
	  - PickupArea（Area2D + CollisionShape2D）：拾取检测
	  - Visual（Polygon2D 等）：钥匙外观
	Door 的 required_key_id 填这里的 key_id 即可关联。

--------------------------------------------------------------
9. scripts/lever.gd  （class_name Lever，拉杆/开关）
--------------------------------------------------------------
  功能：
	玩家走过切换开关，写入 GameState.switches，驱动 Gate(switch) 开门。
  属性：
	  lever_id   开关 id（默认取节点名）
	  starts_on  初始是否已开启（默认 false）
  使用方法：
	放 Node2D 挂此脚本，子节点：
	  - InteractArea（Area2D + CollisionShape2D）：触碰检测
	  - Visual：外观
	Gate 的 gate_type="switch"、required_id=此 lever_id 即可关联。

--------------------------------------------------------------
10. scripts/gate.gd  （class_name Gate，门控障碍）
--------------------------------------------------------------
  功能：
	三种解锁条件（gate_type）：key / ability / switch。
	条件满足即开启。锁存（一旦打开不再关闭，避免软锁）。
  属性：
	  gate_id      门 id（默认取节点名）
	  gate_type    解锁类型：none / key / ability / switch
	  required_id  对应的 key_id / ability_id / switch_id
	  starts_open  初始是否已开（默认 false）
  使用方法：
	放 Node2D 挂此脚本，子节点：
	  - Body（StaticBody2D + CollisionShape2D）：挡路碰撞
	  - Visual：外观
	例：gate_type="switch", required_id="lever_a" → 拉杆 lever_a 打开它。

--------------------------------------------------------------
11. scripts/breakable_wall.gd  （class_name BreakableWall，可破坏墙）
--------------------------------------------------------------
  功能：
	玩家触碰破坏（白盒占位，后续可接颜色/能力破坏）。
	破坏状态会被保存/恢复。
  属性：
	  wall_id  墙 id（默认取节点名）
  方法：
	  break_wall()  手动破坏
  使用方法：
	放 Node2D 挂此脚本，子节点：
	  - BreakArea（Area2D + CollisionShape2D）：破坏检测
	  - Body（StaticBody2D + CollisionShape2D）：挡路碰撞
	  - Visual：外观

--------------------------------------------------------------
12. scripts/pushable_box.gd  （class_name PushableBox，可推箱）
--------------------------------------------------------------
  功能：
	可推动的箱子，物理由子节点 RigidBody2D 承载（重力=0、锁定旋转）。
	位置会被保存/恢复。
  使用方法：
	放 Node2D 挂此脚本，子节点：
	  - Body（RigidBody2D，内含 CollisionShape2D + Visual）
	直接放场景即可，玩家碰撞即可推动。

--------------------------------------------------------------
13. scripts/game_hud.gd  （game.tscn 的 HUD）
--------------------------------------------------------------
  功能：
	显示：当前颜色 / 持有的钥匙 / 当前房间 / 提示文字（2 秒后消失）。
  依赖：
	玩家脚本需提供 color_changed 信号 + selected_color、
	selected_color_name 属性（现有 color_change 系统已满足）。
  使用方法：
	一般无需改逻辑；改显示样式在 game.tscn 的 Label 上改。

--------------------------------------------------------------
14. scripts/room_meta.gd  （class_name RoomMeta，房间元数据）
--------------------------------------------------------------
  功能：
	单个房间的持久化元数据：is_visited / is_cleared /
	collected_items / stateful。由 GameState 按房间 id 保存。
  使用方法：
	一般不需要直接操作，通过 GameState 的方法间接使用。

--------------------------------------------------------------
15. scripts/reachability.gd  （class_name Reachability，软锁检查）
--------------------------------------------------------------
  功能：
	BFS 可达性检查：根据关卡图（房间/门/钥匙）检测软锁。
	状态 = (房间, 已持有钥匙集合)。锁门需要钥匙已在集合中才能通过。
	注：开关/能力门默认视为「到达该房间即可解开」，不参与 BFS。
  关键方法：
	  test_graph()     测试用关卡图（关卡策划需在此维护真实图）
	  check(...)       核心 BFS
	  self_test()      跑一遍 test_graph
	  format_report()  格式化结果
  使用方法：
	在 Godot 编辑器里或游戏内调用 GameState.debug_reachability()
	打印结果；正式使用时把 test_graph() 换成真实关卡数据。

【三、场景文件说明】

  scenes/game.tscn   主场景（常驻：GameContainer + Player + HUD）
  rooms/room_a.tscn  房间 A：3 个门（含 1 个锁门）、拉杆+门、可破坏墙
  rooms/room_b.tscn  房间 B：返回门、拉杆+门、钥匙、可推箱
  （这些是示例关卡，供你参考结构；正式关卡请复制后改）

----------------------------------------------------------------

【四、如何新增一个房间 / 门 / 机关】

  新增房间：
	1) 新建 Node2D 场景，根节点挂 room.gd，设 room_id + camera_limits。
	2) 加 Ground（Polygon2D）、入口（Entrance）、门（Door）等。
	3) 保存到 rooms/ 下。

  连接两个房间：
	在 A 房放 Door（target_scene = B 房路径，target_entrance = B 房入口 id），
	在 B 房对应位置放 Entrance（entrance_id 与之一致）。

  新增一种机关：
	继承 StatefulObject，实现 save_state()/restore_state()，
	需要挡路就在子节点放 StaticBody2D + CollisionShape2D，
	需要检测就放 Area2D 连 body_entered。

【五、已验证（2026-10-03 实测通过）】

  已通过 Godot MCP 实际运行验证：
	- 房间切换：room_a ↔ room_b 往返，玩家定位到正确入口（-400,0）
	- HUD：房间名 / 颜色 / 钥匙实时刷新
	- 钥匙拾取：has_key 变 true，钥匙视觉隐藏
	- 锁门：持有钥匙后 _is_locked 变 false
	- 拉杆→门：set_switch 后门打开（碰撞禁用、视觉隐藏），且锁存
	- 可破坏墙：破坏后碰撞禁用、视觉隐藏
	- 状态保存/恢复：切房往返后，门保持打开、墙保持已破坏
	- 软锁检查：可达房间 ["room_a","room_b"]，无软锁

【六、注意事项 / 已知要点】

  1) 改 project.godot 后，运行中的编辑器不会自动热加载，
	 若改了 autoload 或 main_scene，需重开项目（或重载）才生效。
  2) game_eval（MCP 调试）里不要写 for/if/await，会解析失败。
  3) 2.5D 是视觉风格（Polygon2D 伪 3D），本质是纯 2D；
	 地面圆环类效果需考虑斜视角的椭圆压扁。
  4) Area2D 默认会检测父节点，调试时用 collision_layer 分层隔离。
